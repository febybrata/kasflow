Two-tier layout:
- `components/ui/` — dumb, theme-aware primitives (button, input, badge, card, modal, drawer, select, tabs, skeleton, empty-state, data-table) built on Tailwind + `@/lib/utils/cn`, consumed by everything above.
- `components/` — application-level presentational components: `providers.tsx` is the root client provider wrapping `QueryClientProvider` → `AuthProvider` → children with a Sonner `Toaster`; `app-shell.tsx` guards unauthenticated routes, shows a loading spinner while Supabase session resolves, then renders `TopNavBar` + page content + `BottomTabBar`; `auth-provider.tsx` owns the Supabase auth lifecycle (`getSession`, `onAuthStateChange`) and bootstraps a company via `bootstrapCompanyForUser` when no profile exists; `top-nav-bar.tsx` / `bottom-tab-bar.tsx` render desktop dropdowns and mobile tab rails driven by `usePathname`; `more-sheet.tsx`, `client-only-chart.tsx`, `metric-card.tsx` are feature-specific shells.
- `hooks/` — pure React hooks with no component coupling: `use-paginated-transactions.ts` wraps cursor-based pagination over `getTransactionsPaginated` with optimistic local mutations; `use-debounced-value.ts` is a generic debounce utility.

Dependency direction is strictly downward: `ui/*` has no app knowledge; `components/*` depends on `ui/*`, `@/lib/supabase/*`, `@/store/*`, and `@/lib/types`; hooks depend only on `@/lib/supabase/*` and `@/lib/types`. The module never imports Next.js pages or route handlers.
