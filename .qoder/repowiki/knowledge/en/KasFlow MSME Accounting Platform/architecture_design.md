The workspace is a flat Next.js project (Next 15 + React 19) with no monorepo tooling — children are sibling directories consumed via the `@/*` path alias defined in `tsconfig.json`. The runtime entrypoint is the Next.js server (`next dev/build/start` from `package.json`) which boots `app_pages` as the App Router shell; `ui_components` provides the authenticated layout and shadcn primitives used by those pages; `shared_libs` exports the Zod schemas, Supabase client, marketplace adapters, and Zustand store that both the server-side API routes and client components import. Data evolution lives under `data_scripts/` as date-stamped SQL migrations applied to Supabase Postgres, while the many `check-*.ts`, `sum-*.ts`, `patch-*.ts`, `manual-sync*.ts`, and `test_*.js` files at the root are ad-hoc CLI/data-migration scripts that import directly from `shared_libs` against the live database. `reference_docs/` holds product requirements and schema artifacts referenced during development but not compiled into the build.
