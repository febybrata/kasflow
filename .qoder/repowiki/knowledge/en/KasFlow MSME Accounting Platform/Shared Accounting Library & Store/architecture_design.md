This scope is a flat aggregation of three sibling child modules plus two top-level files:
- `lib/` holds the runtime library: `supabase/` (client + company bootstrap + typed schema + CRUD service), `marketplace/` (Shopee/TikTok adapter contracts + implementations), `accounting.ts` / `accounting-memoized.ts` (memoized domain helpers), `types.ts` (shared Zod schemas + domain types), `utils.ts`, `toast.ts`, `validation.ts`, `report-export.ts`, and `memoize.ts`. The children are wired together at import time — e.g. `marketplace_adapters` imports `shared_utils` for domain types and `supabase_client` for DB access; `accounting.ts` re-exports memoized variants of those helpers.
- `store/use-kasflow-store.ts` is the single Zustand store instance that both the UI layer and the accounting services read/write to keep in-memory state in sync with Supabase realtime events.
There is no orchestrator entry point or index barrel; consumers import directly from `lib/supabase`, `lib/marketplace`, `lib/accounting`, etc., so isolation between children is enforced purely by package boundaries and explicit import paths rather than a central registry.
