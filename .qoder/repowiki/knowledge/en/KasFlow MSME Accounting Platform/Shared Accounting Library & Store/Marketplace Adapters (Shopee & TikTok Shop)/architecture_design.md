Each subdirectory (`shopee/`, `tiktok/`) is a self-contained adapter implementing the same four-file contract: `auth.ts` (token refresh), `client.ts` (HTTP wrapper with retry/backoff), `sync-engine.ts` (stage orchestrator), and per-resource `sync-*.ts` modules. The sync engine in every adapter follows an identical flow — Stage 1 syncs statements (creating KasFlow transactions via `create-transactions.ts`), Stage 2 syncs orders as analytics cache, and optionally Stage 3 syncs unsettled/settlement data — all driven by shared domain types imported from `@/lib/types` (`MarketplaceConnection`, `MarketplaceStatement`, `MarketplaceOrder`, `MarketplaceSyncLog`, `Category`, `CashAccount`). Each adapter exposes its own `runSync(params)` entry point returning a typed `SyncEngineResult` plus a `createSyncLogFromResult` helper, so callers dispatch to the correct adapter without knowing platform internals. Platform-specific wire-up (shopId vs shopCipher, partnerId/partnerKey vs appKey/appSecret) lives only in the adapter's `SyncEngineParams`; the rest of the system consumes the uniform result shape.
