Four Next.js App Router route handlers under `app/api/integrations/shopee/`, each exposing a single HTTP verb to an external consumer:
- `auth/route.ts` (POST) — builds the Shopee OAuth authorize URL via `@/lib/marketplace/shopee/auth.generateAuthUrl`, embedding `companyId` as the `state` query param.
- `callback/route.ts` (GET) — exchanges the returned `code` for tokens through `exchangeAuthCode`, fetches shop info via `shopeeApiGet`, then upserts a `marketplace_connections` row and seeds four default `marketplace_account_mapping` rows (`revenue`, `platform_fee`, `receivable`, `settlement_bank`).
- `sync/route.ts` (POST) — validates an active connection, proactively refreshes the access token via `refreshAccessToken` when `shouldRefreshToken` is true, runs the heavy lifting in `@/lib/marketplace/shopee/sync-engine.runSync`, then batches upserts `marketplace_statements` (new ones land with `approval_status: pending_approval`) and `marketplace_orders` (50-row batches on conflict of `connection_id,platform_order_id`), recording progress in `marketplace_sync_logs`.
- `approve/route.ts` (POST) — takes a list of pending statement IDs, calls `createTransactionsFromStatement` + `generateJournalFromTransaction` to produce double-entry journal lines, inserts both `transactions` and `journal_entries` rows (snake_case ↔ camelCase conversion helpers bridge DB and domain models), and marks statements `approved` / `reconciled`.

Dependency direction is one-way: routes depend on shared libs under `@/lib/marketplace/shopee/*` and `@/lib/accounting`; they never import from sibling integration modules. All persistence goes through a service-role Supabase client constructed per request using `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Environment-driven configuration uses `SHOPEE_PARTNER_ID` / `SHOPEE_PARTNER_KEY` plus `NEXT_PUBLIC_APP_URL` for redirect URIs.
