Each subdirectory under `app/api/integrations/tiktok/` is a Next.js App Router route handler (`route.ts`) that owns one REST endpoint. The module has no shared server code — it delegates platform-specific logic to pure helpers in `@/lib/marketplace/tiktok/*` (auth token exchange, sync engine, transaction creation) and to the accounting journal generator in `@/lib/accounting`. Data access goes through the Supabase service-role client (`SUPABASE_SERVICE_ROLE_KEY`, bypassing RLS); some read endpoints also call the Supabase REST `/rest/v1/` endpoint directly. Endpoints fall into four groups: (1) OAuth lifecycle — `auth/route.ts` POST builds the TikTok authorize URL with a `companyId_uuid` state; `callback/route.ts` GET exchanges the code, persists `marketplace_connections`, and seeds default `marketplace_account_mapping` rows; (2) connection & catalog — `connections`, `shops`, `categories`, `cash-accounts`; (3) data sync — `sync/route.ts` orchestrates `runSync`, upserts statements/orders/unsettled into `marketplace_*` tables, and records progress in `marketplace_sync_logs`; (4) accounting workflow — `statements/`, `statements/pending/`, `approve/`, `reject/` move statements from `pending_approval` → `approved`/`rejected`, and `approve` creates KasFlow transactions + journal entries via `createTransactionsFromStatement` + `generateJournalFromTransaction`. All routes validate inputs, return `{ error, ... }` JSON on failure, and log with `[Tag]` prefixes.
