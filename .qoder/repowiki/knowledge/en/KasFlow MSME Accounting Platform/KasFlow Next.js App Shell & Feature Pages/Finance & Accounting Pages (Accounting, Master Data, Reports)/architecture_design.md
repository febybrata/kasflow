Three sibling Next.js App Router pages (`app/accounting/page.tsx`, `app/master-data/page.tsx`, `app/reports/page.tsx`), each a single-file `'use client'` React component with no sub-routes. All three share the same data layer: state is read/written through the Zustand store `@/store/use-kasflow-store` (accounts, journalEntries, ledgerEntries, categories, cashAccounts, customers, suppliers, auditLogs, etc.), while server-side persistence is triggered via `@/lib/supabase/company-service` functions when `appUser` is present; otherwise mutations are applied only to local store state. UI is composed from shared primitives in `@/components/ui/*` (Card, Button, Table, Drawer, ConfirmModal, Badge) and `lucide-react` icons. The accounting page owns period lifecycle (open/close, opening balance, COA CRUD); the master-data page owns entity CRUD for categories/cash-accounts/contacts using inline drawers plus a centralized delete-confirmation modal; the reports page is read-only — it computes P&L, balance sheet, bruto tax, and cash flow via memoized helpers in `@/lib/accounting-memoized` and renders Recharts AreaChart inside a `ClientOnlyChart` wrapper, with PDF/Excel export delegated to `@/lib/report-export`. Dependency direction is one-way: pages → store + service + shared UI; there is no cross-import between these three pages.
