Three sibling Next.js Route Handler pages (`app/settings/page.tsx`, `app/onboarding/page.tsx`, `app/utilities/page.tsx`) that are pure client components (`"use client"`). Each page is a self-contained React component with no shared sub-components — cross-page state is coordinated through the global Zustand store `@/store/use-kasflow-store` (profile, cashAccounts, accountingPeriods, transactions, etc.) and the auth context `@/components/auth-provider`. Server-side persistence goes through `@/lib/supabase/company-service` (`updateBusinessProfile`, `createOpeningBalance`, `bulkInsertTransactions`, `resetCompanyData`, restore helpers), while seed/demo data generation lives in `@/lib/accounting` (`createSeedTransactions`, `createDemoCustomers`, `createOpeningBalanceJournal`, `generateJournalFromTransaction`). The three pages form a user journey: Settings → links to Onboarding wizard → finishes back at `/`; Utilities is an admin-only tooling surface. There is no internal layering beyond these three files; they depend outward on `@/components/ui/*`, `@/lib/*`, and `@/store/*`.
